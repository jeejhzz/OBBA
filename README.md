# OBBA — Oliveyoung Beauty Browser Assistant

> 상황과 피부 고민만 고르면, 올리브영에서 뭘 사면 되는지 골라주는 모바일 대화형 어시스턴트.

올리브영에는 제품이 너무 많다. OBBA는 **"지금 나한테 필요한 거 3개"까지 좁혀주고, 그중 뭘 살지 정해주는 것**까지만 한다.
담고 결제하는 건 올리브영이 잘한다. 고르는 걸 대신해 주는 게 이 앱의 일이다.

```
$ npm run serve          # http://127.0.0.1:8137
```
빌드 산출물(`assets/css/obba.css`)이 저장소에 커밋되어 있어서, **받아서 바로 열면 동작한다.**
GitHub Pages에 그대로 올려도 되고, 외부 네트워크 없이 오프라인에서도 똑같이 뜬다.

스타일을 고칠 때만 빌드가 필요하다.

```
$ npm install            # 최초 1회
$ npm run build:css      # assets/css/obba.src.css → assets/css/obba.css
$ npm run watch:css      # 작업 중에는 이걸로
$ npm test               # 카탈로그 스키마 + 16조합 회귀 검사
```

## 휴대폰에서 앱처럼 쓰기

GitHub Pages로 띄운 주소를 폰 브라우저에서 열고 **홈 화면에 추가**하면 끝이다.
아이콘이 생기고, 주소창 없이 전체화면으로 뜨고, **비행기 모드에서도 열린다.**

- 안드로이드/크롬: 앱 안에 뜨는 `추가하기` 버튼 한 번
- 아이폰/사파리: 공유 버튼 → `홈 화면에 추가` (앱이 안내를 띄워준다)

오프라인 동작은 서비스워커(`sw.js`)가 담당한다. 외부 CDN을 전부 걷어냈기 때문에
캐시만으로 완전히 자립한다 — 처음 한 번 열어두면 그 뒤로는 인터넷이 없어도 상담이 된다.
(상품 링크를 눌러 올리브영으로 넘어가는 것만 인터넷이 필요하다)

### 주소 만들기 (최초 1회)

저장소 **Settings → Pages → Source: Deploy from a branch → 브랜치 선택 → /(root) → Save**.
1~2분 뒤 `https://jeejhzz.github.io/OBBA/` 로 열린다. 이후에는 푸시할 때마다 자동 반영된다.

## 무엇을 하는가

1. **피부타입 → 상황 → 고민** 3단계 질문. 각 단계는 버튼 한 번 또는 자연어 한 줄로 넘어간다.
   - `"나 지성인데 야근하고 와서 트러블 났어 가성비로 추천해줘"` → 세 축을 한 번에 파싱해서 바로 추천으로 점프
2. **추천 카드 3장**을 가로 스와이프로 제시. 각 카드에는 왜 골랐는지가 칩으로 붙는다
   (`오빠 픽` / `지성 피부에 잘 맞음` / `1만원 이하 예산 OK`).
3. **비교 뷰**에서 가격·타깃·핵심 성분·제형을 나란히 놓고, 프로필 기준으로 결론을 낸다.
4. **제형 취향**(가벼움/쫀쫀함)을 고르면 즉시 재추천 — 취향이 다음 대화에도 계속 남는다.
5. 마음에 드는 걸 누르면 **올리브영 상품 페이지로 바로** 넘어간다.

프로필은 `localStorage`에 남아서, 다시 들어와도 오빠가 나를 기억한다.

### 하지 않는 것

- **장바구니·결제** — 담아도 결국 올리브영에서 다시 담아야 한다. 화면만 복잡해지고 하는 일은 없었다.
- **립/메이크업** — 지금의 추천 축(수분·진정·미백·결)으로 매핑되지 않는다. 억지로 넣으면 "트러블에 좋은 틴트"가 나온다.

### 외부 의존성 없음

폰트·스타일·아이콘을 전부 저장소 안에 넣었다. 런타임에 나가는 네트워크 요청은 **0건**이다.

| | 이전 | 지금 |
|---|---|---|
| CSS | `cdn.tailwindcss.com` 런타임 JIT | 빌드된 20KB CSS |
| 아이콘 | Font Awesome 전체 (~150KB webfont) | 인라인 SVG 8개 (2.3KB) |
| 폰트 | jsDelivr → Pretendard static | 로컬 dynamic subset (필요한 청크만 다운로드) |

부수 효과 하나: 브랜드 컬러를 Tailwind 테마(`--color-olive`)에 등록해서
`ring-olive/50` 처럼 **CDN 시절엔 조용히 무효였던 클래스들이 이제 실제로 동작한다.**

### 추천이 만들어지는 방식

**큐레이션(사람) + 스코어링(개인화)** 하이브리드다.

- 상황×고민 16조합에는 사람이 쓴 코멘트와 대표 상품이 항상 붙는다 → 말투와 근거의 품질을 보장
- 그 위에서 프로필로 점수를 매겨 순서를 바꾸고, 후보가 부족하면 카탈로그에서 보강한다

```
고민 일치 +30 · 상황 일치 +15 · 피부타입 일치 +25(불일치 −20)
제형 취향 일치 +15(정반대 −10) · 예산 이내 +10(초과 −25) · 30%↑ 할인 +8 · 큐레이션 +20
```

같은 "데이트 × 수분"이라도 지성이면 토리든 세럼이, 건성이면 에스트라 크림이 1번 카드로 온다.
점수와 함께 **사람이 읽을 수 있는 이유**를 같이 리턴하기 때문에 UI가 근거를 그대로 보여줄 수 있다.

## 올리브영 연동

지금은 **딥링크 방식**이다. 21종 중 11종은 상품번호(`goodsNo`)를 확보해 상세페이지로 직행하고,
나머지는 검색 결과로 폴백한다. 전부 채우지 않은 건 게을러서가 아니라 정책이다 —
올리브영은 같은 제품을 단품·기획·리필로 여러 SKU로 파는데 기획 SKU는 시즌마다 교체되므로,
**안정적인 단품 리스팅이 있는 상품만 채우는 게 링크가 썩지 않는 방법**이다.
확보 근거와 잔여 목록은 [docs/GOODSNO-REVIEW.md](docs/GOODSNO-REVIEW.md).
카탈로그 스키마만 지키면 데이터 출처는 나중에 통째로 갈아끼울 수 있다.
선택지별 장단점과 이행 계획은 [docs/OLIVEYOUNG-INTEGRATION.md](docs/OLIVEYOUNG-INTEGRATION.md) 참고.

## 알려진 제약

- 가격/할인율은 **하드코딩된 스냅샷**이고, 실제로 몇 건은 이미 어긋난 것이 확인됐다
  (예: 넘버즈인 3번 세럼 22,000 → 실제 30,000원대). 목록은 GOODSNO-REVIEW.md 참고.
  근본 해결은 시트 기반 카탈로그로 가격을 배포에서 분리하는 것.
- 자연어 인식은 형태소 분석 없이 **가중치 키워드 매칭 + 자모 단위 오타 보정**이다.
  사전에 있는 말(과 그 오타)만 알아듣는다. 처음 보는 표현은 여전히 모른다.
  못 알아들은 말은 기기 안에 기록되고(`기록` 입력) 그게 사전을 넓히는 재료가 된다.
  절차: 기록 확인 → `tools/check-nlu.js` 에 케이스 추가 → `flows.js` 사전 보강 → `npm test`.
  진짜 언어 이해가 필요해지면 LLM 파서(로드맵 P2)로 가야 한다.
