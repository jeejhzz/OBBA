# goodsNo 확보 현황 (2026-08 기준)

`goodsNo`가 있으면 상세페이지로 직행하고, 없으면 검색 결과로 폴백한다.
아래는 웹 검색으로 확보한 결과와, **사람이 5분만 확인하면 되는 잔여 목록**이다.

> ⚠️ 확인의 한계: 상품 페이지를 직접 열어 검증하지는 못했다(작업 환경에서 oliveyoung.co.kr 접근 차단).
> 검색 결과의 제목·URL·가격 정보가 서로 수렴하는 경우만 채택했고, 근거는 `goodsNoSource` 필드에 남겼다.
> 링크를 한 번씩 눌러보고 이상하면 알려주면 바로 고친다.

## 함께 발견한 것 — 가격이 낡았다

goodsNo를 찾는 과정에서 카탈로그 가격이 현재 판매가와 어긋난 사례가 여럿 확인됐다.

| 상품 | 카탈로그 | 검색에서 확인된 현재가 |
|---|---|---|
| 넘버즈인 3번 결 세럼 | 22,000 → 15,400 | 30,000 → 22,500 |
| 에스트라 아토베리어365 크림 | 31,000 → 24,800 | 31,000 → 22,300 |
| 메이크프렘 클렌징폼 | 16,000 → 12,800 | 18,000 → 15,300 (1+1) |
| 케어플러스 스팟패치 | 6,500 → 5,520 | 6,300 → 5,900 |

메디힐 티트리(2,000→1,000)처럼 그대로인 것도 있지만, 세일 주기마다 바뀌는 값을 코드에 박아두는 구조 자체가 원인이다.
→ **다음 작업은 시트 기반 카탈로그**([OLIVEYOUNG-INTEGRATION.md](OLIVEYOUNG-INTEGRATION.md) §1-B).
가격을 앱 배포에서 분리하면 이 표는 다시 만들 필요가 없어진다.

## 유지보수 메모

기획(번들) SKU는 시즌마다 교체된다. 기획 goodsNo를 박아두면 언젠가 판매종료 페이지로 간다.
그래서 **단품 SKU가 안정적으로 존재하는 상품만 goodsNo를 채우는 것**이 기본 정책이고,
기획만 있는 상품은 검색 폴백이 오히려 더 튼튼하다. 위 '보류' 중 상당수가 이 경우다.
