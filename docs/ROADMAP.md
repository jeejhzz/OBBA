# OBBA 로드맵

## 완료 (v1)

- 단일 HTML → 데이터/엔진/렌더/컨트롤러 분리
- 큐레이션 + 스코어링 하이브리드 추천 엔진, 추천 근거를 카드에 노출
- 피부타입·예산·제형 취향 프로필 (localStorage 유지) → 같은 조합도 사람마다 다른 순서
- 자연어 한 줄로 3단계 건너뛰기 (`"지성인데 야근하고 트러블 났어 가성비로"`)
- 루틴 순서 정렬 장바구니, 절약액 합계, 쇼핑 리스트 텍스트 복사
- 사용자 입력 이스케이프, 인라인 onclick 제거, 포커스 링·모션 최소화·safe-area 대응

## P1 — 다음에 할 것

- [ ] **상품 `goodsNo` 채우기** — 검색 경유 없이 상세페이지 직행 (docs/OLIVEYOUNG-INTEGRATION.md §0)
- [ ] **시트 기반 카탈로그 + 폴백** — 가격 갱신을 앱 배포에서 분리
- [ ] **CDN 의존 제거** — Tailwind/Font Awesome/Pretendard를 정적 파일로 내재화. 지금은 CDN이 막히면 UI가 무너진다
- [ ] **함께 쓰기** — 커플이 각자 프로필을 갖고 서로 장바구니를 공유. URL 해시로 리스트를 주고받는 정도면 서버 없이 가능
- [ ] **성분 충돌 경고** — 레티놀 + BHA 같은 조합을 장바구니에서 잡아준다. 이게 "추천"을 "상담"으로 바꾸는 지점

## P2 — 서비스로 키운다면

- [ ] **루틴 빌더** — 낱개 추천 대신 아침/저녁 루틴 한 세트를 순서대로 제안
- [ ] **재구매 알림** — 용량과 사용 주기로 소진 시점을 추정해서 다시 대화를 연다
- [ ] **세일 캘린더** — 올영세일 주기를 반영해 "지금 살지, 세일 때 살지" 판단을 붙인다
- [ ] **피부 일지** — 트러블 사진/컨디션 기록 → 계절별 패턴 파악
- [ ] **LLM 상담 레이어** — 키워드 매칭 대신 실제 언어 이해로. 단, 추천 후보는 반드시 카탈로그로 제한하고
      (환각 방지) 큐레이션 코멘트의 말투는 유지한다
- [ ] **평가 셋** — "이 입력에는 이 상품이 나와야 한다" 케이스를 모아 회귀 테스트. 엔진 점수 조정 시 필수

## 하지 않기로 한 것

- 상품 페이지 크롤링 (약관·저작권·차단 리스크 대비 이득이 적음)
- 앱 안에서의 결제 — 결제는 올리브영에서. OBBA는 "고르는 것"까지만 책임진다
- 별점/리뷰 수 표시 — 출처 없이 만들어내면 그건 거짓말이다. 실제 데이터가 연동되기 전까지는 안 쓴다
