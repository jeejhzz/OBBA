# OBBA 로드맵

## 완료 (v1)

- 단일 HTML → 데이터/엔진/렌더/컨트롤러 분리
- 큐레이션 + 스코어링 하이브리드 추천 엔진, 추천 근거를 카드에 노출
- 피부타입·예산·제형 취향 프로필 (localStorage 유지) → 같은 조합도 사람마다 다른 순서
- 자연어 한 줄로 3단계 건너뛰기 (`"지성인데 야근하고 트러블 났어 가성비로"`)
- 루틴 순서 정렬 장바구니, 절약액 합계, 쇼핑 리스트 텍스트 복사
- 사용자 입력 이스케이프, 인라인 onclick 제거, 포커스 링·모션 최소화·safe-area 대응

## 완료 (v1.1)

- CDN 의존 전면 제거 — Tailwind 빌드 CSS(20KB), 아이콘 인라인 SVG(2.3KB), Pretendard 로컬 subset
- 브랜드 컬러를 Tailwind 테마에 등록 → `bg-olive` / `ring-olive/50` 이 실제 유틸리티로 동작
- `npm test` — 카탈로그 스키마·참조 무결성·16조합 추천 회귀 검사

## 완료 (v1.2)

- 홈 화면에 추가하면 앱처럼 뜨는 형태(PWA) — 아이콘, 전체화면, 오프라인 동작
- 안드로이드는 설치 버튼, 아이폰은 공유 메뉴 안내로 분기 (한 번 닫으면 다시 안 뜸)
- 링크 하나로 여는 단일 파일 빌드 (`npm run build:artifact`)

## 완료 (v1.3)

- 자연어 인식 개선 — 구어체 사전 확장("난리 났어", "뒤집어졌어", "화장이 안 먹어", "개기름"),
  첫 일치가 아니라 가중치 점수로 축별 최선을 고름, 띄어쓰기 무시
- 부분적으로만 알아들었을 때의 응답 수정 — 고민만 말하면 상황만, 상황만 말하면 고민만 묻는다
  (기존에는 고민을 알아듣고도 "그 상황은 공부 중이야"라고 답했다)
- 자연어를 먼저 말한 뒤 버튼을 누르면 이미 아는 정보를 다시 묻던 흐름 버그 수정
- `tools/check-nlu.js` 45문항 시험지 — 못 알아듣는 말이 나오면 한 줄 추가하는 게 절차

## 완료 (v1.4)

- **장바구니 제거** — 담아도 올리브영에서 다시 담아야 하는 반쪽 기능이라 화면만 복잡하게 만들었다.
  카드 CTA를 "올리브영에서 보기" 하나로 정리하고, 헤더·바텀시트·수량 조절을 전부 걷어냈다.
  프로필(피부타입·예산·제형)은 그대로 유지 — 추천 품질의 핵심이라서.
- 앱의 범위를 명시: **묻고 → 고르고 → 비교하는 것까지.** 담고 결제하는 건 올리브영의 일.

## 완료 (v1.5)

- **오타 보정** — 한글을 자모로 풀어 편집거리로 비교. "트러불", "여드럼", "뾰루찌", "건조헤서" 를 알아듣는다
- **되묻기** — 확신은 못 해도 짚이는 게 있으면 "혹시 이 얘기야?" 로 한 번 물어본다 (막다른 길 제거)
- **못 알아들은 말 기록** — 기기 안에만 최근 30개 저장, `기록` 입력으로 열람. 사전 확장의 재료
- 흐름 버그 수정 — 앞서 고민을 알아들은 뒤에는 이후 입력을 못 알아들어도
  같은 질문만 반복하며 기록도 되묻기도 하지 않던 문제
- 오탐 제거 — "주말에 영화 보러 갈까" 가 데이트로 잡히던 문제(`보러가` 키워드 삭제)
- 시험지 45 → 56문항 (오타 6, 오탐 방지 5 추가)

## P2 — 서비스로 키운다면

- [ ] **루틴 빌더** — 낱개 추천 대신 아침/저녁 루틴 한 세트를 순서대로 제안
- [ ] **세일 캘린더** — 올영세일 주기를 반영해 "지금 살지, 세일 때 살지" 판단을 붙인다
- [ ] **피부 일지** — 트러블 사진/컨디션 기록 → 계절별 패턴 파악
- [ ] **LLM 파서** — 말을 이해하는 건 LLM 에 맡기고, 추천·비교는 지금 엔진 그대로.
      LLM 은 상품명을 절대 말하지 않으므로 환각이 원천 차단된다.
      정적 사이트에 API 키를 둘 수 없어 작은 프록시(Cloudflare Workers 등)가 필요하다.
      실패하면 현재 키워드 방식으로 자동 폴백 — 키워드 매칭 대신 실제 언어 이해로. 단, 추천 후보는 반드시 카탈로그로 제한하고
      (환각 방지) 큐레이션 코멘트의 말투는 유지한다
- [ ] **평가 셋** — "이 입력에는 이 상품이 나와야 한다" 케이스를 모아 회귀 테스트. 엔진 점수 조정 시 필수

## 하지 않기로 한 것

- 상품 페이지 크롤링 (약관·저작권·차단 리스크 대비 이득이 적음)
- 앱 안에서의 장바구니·결제 — OBBA는 "고르는 것"까지만 책임진다 (v1.4에서 장바구니를 실제로 걷어냈다)
- 별점/리뷰 수 표시 — 출처 없이 만들어내면 그건 거짓말이다. 실제 데이터가 연동되기 전까지는 안 쓴다
